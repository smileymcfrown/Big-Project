Core gameplay · 2.5 hours

Sabotage: the OOP showcase

This chapter is where the design pays off. Five different sabotages, one set of rules, and adding a sixth takes about ten lines.

Step 1 · What a dumpling can interact with

Why · NonAlloc physics queries

Physics.OverlapSphere returns a new array every call. Called every frame by four dumplings, that's a steady stream of garbage, and garbage collection pauses are dropped frames, which in VR the chef can feel. OverlapSphereNonAlloc writes into an array we allocated once.

Gotcha · interfaces and destroyed objects

Unity's "fake null" (a destroyed object that == null) only works on variables typed as a Unity object. A destroyed component held in an interface variable is not null. DumplingInteractor.IsAlive handles it; remember the trick for your own interface references.

Step 2 · The base class: rules in one place

Why · the Template Method pattern

Interact() is the template: check the rules, run the hooks, update the score. It's not virtual, so no subclass can forget the cooldown or skip telling the round manager. Subclasses fill in the hooks:

  • OnSabotagedBy(dumpling): one-off effect from a specific dumpling (a shove). Optional.
  • OnSabotaged() / OnRestored(): make the world match the state. Required.

Keep this split in mind: one-off effects vs state. It's exactly the split networking needs in Part 2, and it's why the subclasses won't change there.

Exercise · add a sixth sabotage

Dumplings crank the kitchen radio to full volume; the chef turns it down. Write LoudRadio yourself before peeking. You need: a field for the AudioSource, a normal volume, and the two required overrides.

Show a solution 
using UnityEngine;

namespace DumplingKitchen.Sabotage
{
    public sealed class LoudRadio : SabotageTarget
    {
        [SerializeField] private AudioSource radio;
        [SerializeField, Range(0f, 1f)] private float normalVolume = 0.2f;

        protected override void OnSabotaged() => radio.volume = 1f;
        protected override void OnRestored() => radio.volume = normalVolume;
    }
}

No other file changed: the interactor finds it, the prompt shows it, the score counts it, the alert board lists it, and the chef can fix it with a ChefRestoreHandle. That's the open/closed principle at work.

Couch play on one PC

One PC drives two "audiences": the headset shows the chef's XR camera; the monitor shows up to four dumpling cameras in split-screen. Lara got multi-display output working in NewVRDumpling; here we use split-screen on the main monitor, which needs no extra displays.

Step 2 · What the monitor shows

  1. Add a LobbyCamera: a normal Camera looking over the whole kitchen, with a "Press Start / Enter to join" text on the desktop HUD. No AudioListener.
  2. Add DesktopViewSetup to DumplingJoiner and assign the lobby camera and the Player Input Manager.
  3. Add 4 empty spawn points around the kitchen floor and assign them to LocalPlayerJoiner.
Why · desktop-only cameras

By default every camera can render into the headset. CameraUtility.MakeDesktopOnly sets the camera's target eye to None and turns off URP's XR rendering for it, so dumpling and lobby cameras only draw to the monitor and cost the headset nothing.

Review D19, D20

Up to 4 split-screen dumplings, join with Start/Enter, joining locked during a round, and the headset view is not mirrored to the monitor. If you'd like a spectator view of the chef, set hideHeadsetMirror off and give the lobby camera a corner of the screen.

Gotcha · verify on your hardware

How the XR mirror and desktop cameras share the monitor depends on the runtime. If you see the headset image instead of the split-screen, check both cameras' Target Eye is None, and raise the dumpling cameras' Priority (Depth) above the XR camera's.

Step 3 · Playtest checklist

  1. Headset on (Link or SteamVR), gamepad in hand, Play from the Kitchen scene.
  2. Press Start on the gamepad: a dumpling appears, split-screen kicks in. Press Enter: a second (keyboard) dumpling.
  3. The chef rings the bell: 3, 2, 1, then 5:00 counts down on the wall clock and the monitor.
  4. A dumpling walks to the gas valve: "[X] Turn off Gas" appears. Press it: the flame goes out, the alert board lists it, sabotages = 1.
  5. The chef grabs the valve: flame back, alert cleared. Try sabotaging again immediately: no prompt for 5 s.
  6. Knock the hat (climb a counter): the chef's view goes black until they grab the hat.
  7. Cook and serve 3 dishes: "Dinner is served! Chef wins." Or let the clock run out.

When it all works: git commit -am "Local couch game" && git tag v0.1-local. That tag is your safe point before Part 2 changes things.

Why · a playable vertical slice first

You now have the whole game loop working end to end, ugly but complete. Studios call this a vertical slice. Networking it next means converting something you already know works, so any bug you hit in Part 2 is a networking bug.
